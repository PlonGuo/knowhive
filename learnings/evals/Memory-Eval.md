# Memory 评估:跨会话长期记忆到底有没有用 — Tier 2

**日期**: 2026-07-18 · **模型**: deepseek-chat · **靶场**: 8 条跨会话场景,A/B(记忆 ON vs OFF)
**结论**: **在用户专属、KB 查不到的问题上,长期记忆把答案命中率从 0% 拉到 100%(6 条有效项);
harness 的 OFF 自检抓出 2 条泄漏项,证明测的是记忆不是运气**

## 测什么

自研的三层长期记忆(semantic/procedural/episodic)+ 蒸馏 + 语义召回,到底带来了什么?
用能量化的方式回答:构造"只有靠记忆才答得对"的问题,对比有记忆 / 没记忆两臂。

## 设计(关键在锚点的选择)

每个场景埋一个 **用户专属、KB 里没有、问题本身也没给** 的锚点(公司名/姓名/工具偏好/日期/
自定规则…),然后**开一个全新 session**(无共享历史)问一个依赖该锚点的问题。

- **ON 臂**:清空记忆 → session-1 植入事实 → 等异步蒸馏落表 → 全新 session 提问(记忆在)。
- **OFF 臂**:清空记忆 → 直接提问(记忆不在)。
- **memory_recall** = 答案命中锚点的场景比例。
- **OFF 命中率 = 诚实自检**:一个有效题必须在 OFF **落空**——否则说明锚点能从 KB 或问题里
  推出来,不是真的依赖记忆。

隔离:每个场景跑前 `DELETE FROM memories`(全局记忆会互相污染,eval 必须隔离)。蒸馏是
fire-and-forget,植入后等 6s 并断言 memories 表非空才提问。

## 结果

| | memory_recall |
|---|---|
| **ON** | **8/8 = 1.00** |
| OFF | 2/8 = 0.25 |
| **ON(仅 6 条有效项)** | **1.00**(对应 OFF **0.00**) |

OFF 自检抓出 2 条泄漏:
- `company`:锚点 "Rippling" **本来就在 KB 笔记里**(有一条 Rippling 面试题笔记),OFF 靠检索
  也能答 → 不是记忆功劳,判无效。
- `constraint`:锚点 "中等难度" 是模型的通用默认,OFF 不用记忆也会说 → 判无效。

**排掉这 2 条,6 条纯用户专属事实:ON 100% / OFF 0%。** 自检抓泄漏本身就是 eval 严谨性——
比一个可疑的完美 8/8 更可信。

## 三个决定性对照(同一问题,ON vs OFF)

- **姓名(semantic)**:Q「你还记得我叫什么名字吗?」
  - OFF:「根据提供的文档,其中没有包含您的姓名信息,因此我无法回答。」
  - ON :「Jason,我记得你叫 Jason。」
- **语言偏好(procedural)**:Q(英文)「Give me one tip for reviewing graph algorithms.」
  - OFF:英文作答。
  - ON :中文作答——植入的「always answer in Chinese」被蒸馏成 procedural、无条件注入生效。
- **工具偏好(semantic)**:Q「推荐我练最短路时用什么实现?」
  - 两臂都从 KB 讲 Dijkstra,但只有 ON 补上了用户的「Python / heapq」偏好。

## 诚实边界

- **测的是"召回是否发生",不是答案深度**。ON 全中说明召回可靠,但 spike 里见过一次幻觉
  (模型给记忆事实脑补了「BFS 掌握度 85%」这种没说过的数字)——**记忆注入会放大 faithfulness
  风险**。这条留作后续:给 memory eval 加 RAGAS faithfulness 臂,专门抓"基于记忆的编造"。
- 样本小(有效 6 条),问题偏直接召回(姓名/公司),没测"多跳记忆推理"。够证明记忆通路有效,
  不够证明复杂记忆场景。
- 蒸馏有近重复(11 条 semantic 里几条语义重叠,exact-content dedup 拦不住近似)——不影响召回,
  但长期会撑大记忆表,靠 LRU/TTL eviction 兜。

## 面试点

「我不满足于'我实现了记忆系统',我要能证明它有用。所以我做了个 A/B:构造只有靠记忆才答得对的
跨会话问题,比较有记忆 / 没记忆。有效题上命中率 0%→100%——没记忆时模型直接说'我不知道你叫
什么',有记忆时答得出。最能说明我做 eval 的严谨性的是:我加了个 OFF 臂自检,专门抓'这个锚点
是不是其实能从知识库或问题里推出来',它抓出了 2 条泄漏题(比如公司名恰好在 KB 里),我把它们
判无效而不是塞进分子。我还诚实标了边界:这测的是召回发生没发生,不是答案质量——我在 spike 里
就抓到记忆注入会诱发幻觉,所以下一步要加 faithfulness 臂。做 eval 最怕的是自欺,自检臂就是防这个。」
